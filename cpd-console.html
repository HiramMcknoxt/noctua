Outside witness

Every 7 sim-days the root hash is published outside the system — City Clerk + public repository. Tamper-evidence works because someone else holds a copy.

How to check us

1. Export the log.
2. Recompute the chain — any edited entry breaks every hash after it.
3. Compare the weekly roots against the Clerk's published copies.
4. Compare the chain against the daily signed checkpoints (right, below) — a rewritten chain cannot match a root the Clerk already holds.

The outside auditor's account is read-only and cannot run queries, verify hits, or edit the hot list.

🧪 Try to go around Janus

The bypass test. Janus is supposed to be the only way to plate data — so don't use it. Try the camera software's own interface, its event store, and the database file itself.

What this models: the hardened production configuration — Frigate as a write-only sensor with no human-reachable UI, a rolling buffer measured in minutes instead of an archive, and the plate store reachable only through Janus under a named account. That lockdown is a configuration requirement in the deploy package; this demo shows the intended behavior, and cannot by itself prove a production install is configured that way.

🧪 Full-chain rewrite — the sophisticated insider

The tamper test above catches a careless edit. This is the stronger attack: edit an entry, then recompute every hash in the chain so the log is internally consistent again. Plain chain verification will pass. The daily signed checkpoints — published outside this system, held by the City Clerk — will not.

Reference stack (production path)

Detection/OCR: Frigate LPR or fast-alpr (open source) on commodity cameras · Front door: Janus API (this console's rules, as a service) · Store: PostgreSQL with row-level retention jobs · Log: Sentinel append-only chain, weekly witness publication · Hosting: city-controlled server; the matching step stays on the ACIC/dispatch side unless CJIS Path B is separately approved and priced (spec §4).
