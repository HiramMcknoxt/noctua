    1. Named probes
    1.1 Q16 sink / the third phantom shape (my seat's prior claim)
    Answer: structurally excluded in the shipped Janus wiring; NOT enforced by the Chain class itself.
    The re-read still exists. sentinel.Chain.append:
    entry = self._append_txn(kind, clean)
    if self.db.in_transaction:
        self._deferred.append(entry)
    else:
        self._stream(entry)
    _append_txn decides participate-vs-own-transaction at insert time, but append then re-reads in_transaction outside any guarantee about the caller's transaction lifecycle. The phantom direction: _append_txn participates (caller txn open), another thread rolls the shared connection back before the re-read, the re-read sees False, and _stream publishes a rolled-back entry directly — bypassing the deferred presence check, the ledger, and the watermark.
    Why it cannot fire in 1.2.3 Janus: every chain.append, db.commit, and db.rollback on the shared connection runs under DBLOCK (do_POST/do_GET/do_DELETE wrappers; _flush_config_chain; _note_auth_fail via need_auth inside the lock). R4 removed the last out-of-lock writers (auth/_reload_config no longer chain). Scripts (retention.py, hotlist_sync.py) use private connections single-threaded. So DBLOCK serializes the insert and the rollback; the race window is closed by caller discipline, not by Chain._lock (which a rolling-back thread never takes).
    Disposition: the shape is real at class-contract level and unreachable in current wiring — consistent with Round 6's arbitration of the twin phantom. Cheap hardening, recommended not demanded: have _append_txn return the participation decision captured at insert time and use that flag instead of re-reading in_transaction; document that a shared conn requires external serialization of the transaction lifecycle. The commissioned UI layer (UI-SPEC) is exactly the future caller that could revive this if it shares the connection without DBLOCK. I judge the rebuilt Q16 fault-injection case from the report only (suites not attached); the report's both-shapes PASS is the evidence I have.

    F-A — R6 authorship unenforced on the bulk commitment path. Severity: medium-high (forced-change miss in a named probe).
    janus._rotation_commit: hashes = d.get("nonce_hashes") or {} → membership/hex checks → phase-freeze/no-overwrite → INSERT INTO rotation_contributions … → chain.append("ROTATION_COMMIT", {… "commitments": len(hashes)}). No seed capture (reveals still require partner authorship). The R battery's "unsigned supervisor transport 403" exercises /contribute; this second door appears uncovered.     F-D — destroyed-on-paper bundles: detected, never remediated. Severity: medium (statutory-retention gap; commissioned Qwen residual half-fixed).
